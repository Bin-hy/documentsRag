# API 层与知识库管理 Spec

## 背景

BinRag 已完成核心 RAG 链路：入库 Pipeline（Load→Chunk→Embed→Store）、混合检索（向量+BM25+RRF+重排序）、LLM 集成与 RAG 编排（改写→检索→组装→生成）。这些均为库级能力，没有 HTTP 入口，外部无法使用。

本阶段补齐 API 层：提供 RESTful 接口供前端与外部系统调用——知识库管理、文档上传与异步入库、问答（含 SSE 流式）、对话历史查询，并配套认证、统一响应、日志等基础设施。同时引入 PostgreSQL 持久化元数据（知识库、文档、入库任务、API Key、对话历史），实现多知识库隔离。

## 目标

- 提供 RESTful API：知识库 CRUD、文档上传/列表/删除、问答（普通 + SSE 流式）、对话历史查询
- 多知识库隔离：单一 Qdrant collection + payload filter 方式，入库与检索均携带知识库维度
- 元数据持久化到 PostgreSQL：知识库、文档、入库任务、API Key（存 hash）、对话历史
- 异步入库：上传接口保存文件并创建任务记录后立即返回 task_id；后台 worker pool 执行入库，任务状态持久化、可查询、可重试
- API Key 认证中间件、统一响应格式、请求日志与 CORS 中间件
- 全部参数配置化驱动（端口、数据库连接、存储目录、worker 数等）

## 功能需求

- F1: 知识库管理——创建、列表、查询、更新、删除知识库（元数据存 PostgreSQL）
- F2: 文档上传——接收文件与目标知识库，保存文件到本地磁盘，创建入库任务，立即返回 task_id；入库内容附带知识库与文档维度信息
- F3: 文档列表——按知识库查询文档列表，含文件名、大小、格式、入库状态、创建时间
- F4: 文档删除——删除文档：从向量库删除该文档全部 chunk、从 BM25 索引移除、更新文档记录与任务状态
- F5: 异步入库任务——后台 worker pool 并发执行 Load→Chunk→Embed→Store；任务状态持久化（pending/processing/completed/failed），失败支持自动与手动重试，错误信息可查询
- F6: 问答——接收问题与可选的会话、知识库范围，走 RAG 编排返回回答与引用来源；支持 SSE 流式输出
- F7: 对话历史——会话消息持久化到 PostgreSQL，支持按会话查询历史
- F8: API Key 认证——请求头 `Authorization: Bearer <key>` 校验；Key 以 hash 形式存 PostgreSQL，支持创建、列表、删除、停用
- F9: 统一响应——成功与错误统一 JSON 格式（业务码 + 消息 + 数据）
- F10: 中间件——请求日志（方法/路径/状态码/耗时）、CORS、可选限流
- F11: 配置化——服务端口、PostgreSQL 连接、文件存储目录、worker 并发数等通过 config.yaml 管理

## 非功能需求

- N1: 可用性——核心接口（知识库/上传/问答）在千级文档规模下稳定响应
- N2: 并发安全——worker pool 并发处理多任务、API 并发请求均无数据竞争
- N3: 可恢复——任务状态持久化，服务重启后 pending/processing 任务可恢复处理，不静默丢失
- N4: 可观测——请求日志与任务处理日志完整（开始/结束/耗时/结果）
- N5: 错误隔离——单个文档入库失败不影响其他任务与请求，错误信息可查询、可重试

## 不做的事

- 用户体系 / JWT / RBAC（本阶段用 API Key，预留与知识库绑定的扩展位）
- 前端界面
- 对象存储（文件存本地磁盘，后续可替换为 S3/OSS 等）
- 消息队列调度（后续规模扩大时再把任务调度层替换为 Asynq，业务处理逻辑不变）
- 多实例部署（本阶段单实例 worker）
- 知识库级权限控制（API Key 与 kb 绑定留待后续）

## 验收标准

- AC1: 创建知识库后可通过列表/查询接口看到，含名称与创建时间
- AC2: 上传文档返回 task_id；任务最终变为 completed；文档出现在列表中且状态为入库成功；入库后同知识库内检索可命中该文档内容
- AC3: 上传不支持格式或损坏文件时任务变为 failed，错误信息可查询，且不影响其他任务
- AC4: 删除文档后，该文档的 chunk 不再出现在该知识库的检索结果中
- AC5: 知识库隔离——带知识库范围检索/问答时，结果不包含其他知识库的内容
- AC6: 问答接口返回回答与引用来源；SSE 流式返回引用→增量→结束事件序列
- AC7: 对话历史按会话可查询，多轮消息顺序正确
- AC8: 无 Key、错误 Key、停用 Key 请求返回 401；正确 Key 正常访问
- AC9: 所有接口响应符合统一 JSON 格式（成功与错误均含业务码）
- AC10: 任务失败可重试——手动重试（或自动重试）后任务可变为 completed
- AC11: 服务重启后任务状态不丢失；pending 任务可恢复处理
- AC12: 并发上传多个文档 + 并发问答无 panic、无数据竞争（go test -race 通过）
- AC13: 编译通过 `go build ./...`，全部测试通过 `go test ./...`
