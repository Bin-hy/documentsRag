# 修复空列表返回 null 导致前端白屏 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性
- [ ] 后端 store 层 6 处列表/历史方法空数据返回空 slice（验证：`go build ./...` 通过；空库 curl 返回 `{"data":[]}`）
- [ ] 前端 kb store / doc store / ApiKeysView 赋值处 `?? []` 兜底（验证：`npm run build` 通过，类型检查无错误）

## 接口行为
- [ ] 空库时 `GET /api/v1/knowledge-bases` 返回 `{"data":[]}` 而非 `{"data":null}`（验证：curl 观察响应体）
- [ ] 空文档/空任务/空 Key/空历史时对应接口均返回 `[]`（验证：curl 对应接口观察响应体）
- [ ] 有数据时接口响应格式与字段不变（验证：创建一条知识库后 curl，返回含 `ID`/`Name` 等字段的数组）

## 前端行为
- [ ] 知识库列表页（空库）正常渲染，显示「还没有知识库…」空状态与「新建知识库」按钮（验证：浏览器打开 `/kb`，观察页面与控制台无 TypeError）
- [ ] 知识库详情页 / API Key 页在空数据时不白屏（验证：浏览器分别打开 `/kb/:id`、`/keys` 观察）

## 编译与测试
- [ ] 项目编译无错误（验证：`go build ./...`）
- [ ] 全部单元测试通过（验证：`go test ./...`）
- [ ] `go vet ./...` 无告警
- [ ] 前端构建通过（验证：`cd frontend && npm run build`）

## 端到端场景
- [ ] 场景 1（空库起步）：全新部署（或清空 knowledge_bases）→ 浏览器打开 `/kb` → 页面显示空状态 + 「新建知识库」按钮 → 点击创建 → 知识库出现在列表（验证：浏览器操作 + curl 确认接口返回 `[]` 且创建成功）
- [ ] 场景 2（回归）：已有知识库时列表正常展示、可进入详情、文档/任务列表不白屏（验证：创建知识库后浏览器操作各页面）
