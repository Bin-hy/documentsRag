# 修复空列表返回 null 导致前端白屏 Spec

## 背景

webui 知识库页面打开是空白、没有任何按钮。根因：

1. 后端 store 层列表方法（`ListKBs` / `ListDocuments` / `ListTasks` / `ListAPIKeys` / 对话历史 `Get`）在无数据时返回 Go 的 nil slice，Gin 序列化为 `{"data":null}` 而非 `{"data":[]}`；
2. 前端 `request()` 把 `data` 原样返回，store 赋值为 `null`；
3. 前端视图模板直接访问 `xxx.length`（如 `kbStore.kbs.length === 0`），`null.length` 抛 TypeError，组件渲染失败，页面白屏且无任何按钮。

受影响的页面：知识库列表页、知识库详情页（文档列表）、API Key 页、对话页（历史消息为空时）。

## 目标

- 所有列表/历史类接口在无数据时返回 `[]`（JSON 数组），不再返回 `null`
- 前端对可能为 null 的列表数据做兜底，杜绝 `null.length` 崩溃
- 修复后知识库页面在空库状态下正常显示「新建知识库」按钮与空状态提示

## 功能需求

- F1: 后端 store 层所有列表方法（知识库、文档、任务、API Key、对话历史）在无数据时返回非 nil 空 slice，序列化为 `[]`
- F2: 前端所有从接口获取列表数据的 store 赋值处使用 `?? []` 兜底，保证状态永远是数组
- F3: 前端视图层对列表 `.length` 的访问不再因 null 崩溃（store 层兜底后自然满足，视图层不再需要额外防御）
- F4: 修复后知识库列表页在空库时显示「还没有知识库，点击右上角创建第一个知识库」空状态与「新建知识库」按钮

## 非功能需求

- N1: 行为不变——有数据时的响应格式、字段完全不变，仅空列表从 `null` 变为 `[]`
- N2: 兼容性——现有 api_test 断言不因 `null`→`[]` 而失败（如有断言 `data` 为 null 需同步修正）
- N3: 回归安全——前端其它页面（聊天、上传、API Key）不受影响

## 不做的事

- 不改变统一响应格式（`{code,message,data}`）
- 不新增接口、不改变接口路径与字段
- 不修改 store 层查询 SQL 逻辑（仅初始化返回值）
- 不处理「列表为空但有数据竞争」等无关问题

## 验收标准

- AC1: 空库时 `GET /api/v1/knowledge-bases` 返回 `{"data":[]}` 而非 `{"data":null}`
- AC2: 空文档/空任务/空 Key/空历史时，对应接口均返回 `[]`
- AC3: 浏览器打开知识库页（空库），页面正常渲染，显示空状态提示与「新建知识库」按钮，控制台无 TypeError
- AC4: `go test ./...` 全部通过（含既有 api_test）
- AC5: 前端 `npm run build` 通过
