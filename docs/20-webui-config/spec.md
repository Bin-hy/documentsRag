# WebUI 配置管理界面 Spec

## 背景

BinRag 的系统配置目前只能通过修改 `configs/config.yaml` 并重启服务生效——无运行时查看/修改入口，前端无配置管理界面。检索策略（阶段四）已有知识库级设置，但**全局业务参数**（LLM/Embedding/检索/Reranker/Loader）与**启动级配置**（Postgres/向量存储/Worker/上传目录）均不可在 webui 管理。

本阶段提供 **webui 配置管理界面**：业务参数可查看与修改（写入文件 + 热重载生效），启动级配置只读展示（标记需重启）。

## 目标

- 提供配置管理页面，分组展示全部配置
- 可修改的业务参数（LLM/Embedding/Retriever/Reranker/RAG strategy/Loader）支持编辑、保存并热重载
- 启动级配置（Postgres/VectorStore/Worker/上传目录）只读展示，标记「需重启生效」
- 保存时校验配置合法性（枚举/数值范围/非法组合），拒绝无效修改

## 功能需求

- F1: 配置查看——提供配置管理页面，按组展示当前生效配置（可修改组 + 只读组），分组清晰
- F2: 可修改配置——以下配置可编辑并保存：LLM 模型/温度/超时/最大 token、Embedding 模型/base_url、Retriever top_k/RRF 权重/BM25 开关/重排开关、Reranker 模型/top_n、RAG strategy 六项开关、Loader 可读文本阈值
- F3: 只读展示——以下配置仅展示当前值并标记「需重启生效」：Postgres DSN、VectorStore 地址/维度、Chunker 参数、Server 端口/上传目录/Worker 数
- F4: 保存与热重载——保存修改后：写入 config 文件 → 原子替换运行时配置（ConfigManager）→ 返回重载结果；**新进入的请求使用新配置，已在执行的 RAG pipeline 保持原快照**（请求级 snapshot，单次请求策略一致）；不中断进行中的请求
- F5: 校验——保存时校验：枚举值合法（strategy 六项、provider 等）、数值范围（temperature 0-2、top_k 1-50 等）、非法策略组合（复用 `ValidateStrategy`）；校验失败拒绝保存并返回具体错误
- F6: 重载回滚——热重载失败时（如新配置导致组件初始化失败）回滚到上一份有效配置，服务保持可用
- F7: 生效策略联动——修改 RAG strategy 后，后续问答立即按新策略执行（与阶段四知识库级覆盖兼容：全局默认变化）

## 非功能需求

- N1: 安全——配置管理接口走 API Key 认证；修改接口要求 bootstrap key，避免普通 key 篡改系统配置
- N2: 请求级配置快照（snapshot）——每个请求进入时获取一份配置快照，整个 RAG pipeline（检索/策略/生成）使用该快照，**单次请求生命周期内配置一致**；管理员修改配置仅影响新进入的请求，已在执行的请求保持原快照不受影响
- N3: 原子替换——运行时配置通过统一的配置管理器持有，更新时**原子替换**（旧快照对新请求不可见），避免并发请求读取到写了一半的不完整配置；读端始终拿到完整快照
- N4: 持久化——修改写入配置文件（`configs/config.yaml` 或指定路径），服务重启后仍生效
- N5: 兼容——未修改时行为与现状完全一致；现有 config.yaml 结构不破坏
- N6: 可观测——重载日志记录修改前后配置摘要、重载结果、受影响请求数（可选）

## 不做的事

- 不做完整 yaml 在线编辑（避免绕过校验；用户已确认）
- 不做启动级配置的热修改（Postgres/VectorStore/Worker 等仅展示）
- 不做配置历史/回滚管理（仅保留上一份有效配置用于失败回滚）
- 不做多用户权限体系（沿用 API Key；bootstrap key 才有修改权限）
- 不做配置差异对比/导出

## 验收标准

- AC1: 配置管理页面可访问（认证后），按组展示全部配置，可修改组与只读组区分（验证：浏览器打开 `/settings`，分组可见）
- AC2: 修改 LLM 温度并保存 → 写入 config 文件且热重载成功 → 后续问答使用新温度（验证：保存后观察文件与日志，问答行为变化）
- AC3: 修改 RAG strategy（如 routing=auto）保存 → 全局默认策略更新，问答按新策略执行（验证：保存后问答日志「生效策略」变化）
- AC4: 只读配置（Postgres DSN 等）不可编辑，标记「需重启」（验证：页面只读态 + 标记）
- AC5: 非法配置（temperature=5 / strategy 非法组合）保存被拒绝并返回具体错误（验证：页面错误提示）
- AC6: 热重载失败（如 Embedding base_url 无效）→ 回滚到上一份有效配置，服务可用（验证：构造失败场景，观察回滚与后续请求正常）
- AC7: 普通 API Key 无法修改配置（验证：非 bootstrap key 修改返回 403）
- AC8: 请求级快照一致性——重载发生前后，已在执行的请求用旧配置完成、新请求用新配置（验证：慢请求期间修改配置，观察两个请求分别用新旧配置完成；单测断言 pipeline 内策略不变）
- AC9: 原子替换——并发请求读取配置始终拿到完整快照（无半更新状态）（验证：并发测试或代码审查 ConfigManager 原子替换；race 检测通过）
- AC10: `go build ./...`、`go test ./...`、`go vet ./...` 全部通过；前端构建通过
