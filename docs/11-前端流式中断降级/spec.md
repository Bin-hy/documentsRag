# 前端流式中断降级 Spec

## 背景

BinRag 问答采用 SSE 流式输出（前端 fetch + ReadableStream 手写解析）。前端已实现降级逻辑骨架：error 事件标记消息错误、非 2xx 抛错、AbortController 停止流式、finally 清理流式状态。但 `docs/08-前端界面/checklist.md` 中「流式中断降级」一项**从未实测通过**——各降级场景的实际表现未经验证，可能存在问题。

本阶段对全部降级场景做实测验证，修复发现的问题，补齐 checklist 未勾项。

## 目标

- 逐一实测流式降级各场景，确认或修复其行为符合预期
- 停止按钮、错误提示、消息状态在中断/失败/异常时表现正确，页面不崩溃
- 补齐 `docs/08-前端界面/checklist.md` 的「流式中断降级」勾选项

## 功能需求

- F1: error 事件降级——SSE 流中收到 error 事件时，当前消息标记为错误态，内容显示错误信息，流式状态立即结束，页面不崩溃
- F2: 用户停止中断——点击「停止」后流式立即终止，已收到的内容保留，消息不显示错误态（用户主动中断非错误），发送/停止按钮状态正确恢复
- F3: 网络失败降级——请求中断/网络错误时，消息显示可读错误提示，若已有部分内容则保留并提示不完整
- F4: 非 2xx 响应降级——接口返回 HTTP 错误时，消息显示后端返回的错误信息（优先后端 message，回退 HTTP 状态码）
- F5: 无回答场景——流正常结束但没有产生任何内容时，消息显示「（无回答）」占位，不显示错误态
- F6: 停止按钮状态流转——流式中显示「停止」，结束后（done/error/中断/失败）恢复为「发送」，不会卡死
- F7: 连续操作安全——停止后再发新问题、流式中切换会话/删除会话，均不产生状态错乱或崩溃

## 非功能需求

- N1: 稳定性——上述任一场景下页面无未捕获异常、无控制台报错
- N2: 一致性——消息错误态、流式光标、发送按钮状态在全部场景下逻辑一致
- N3: 可复现——每个场景有明确的复现步骤与预期结果，供回归验证

## 不做的事

- 不新增重试按钮、不新增「重新生成」功能（超出本次降级验证范围）
- 不改造 SSE 传输协议本身（事件格式、后端发送逻辑不改）
- 不改变正常流式问答的展示效果（打字机、引用来源卡片等保持现状）

## 验收标准

- AC1: 后端返回 error 事件时，消息显示错误信息、错误态可见、流式结束、按钮恢复（验证：构造 error 事件实测）
- AC2: 点击停止后内容保留、无错误态、按钮恢复（验证：流式中点停止，观察消息与按钮）
- AC3: 断网/服务不可达时，消息显示可读错误，不崩溃（验证：停后端或断网实测）
- AC4: 后端返回 4xx/5xx 时，消息显示后端 message 或状态码（验证：构造错误响应实测）
- AC5: 空回答流正常结束时显示「（无回答）」（验证：构造空流实测）
- AC6: 全部场景下浏览器控制台无未捕获异常（验证：DevTools 观察）
- AC7: 修复后 `docs/08-前端界面/checklist.md`「流式中断降级」勾选为完成（验证：行为符合描述）
- AC8: 前端 `npm run build` 通过
