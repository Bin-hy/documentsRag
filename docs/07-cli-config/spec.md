# 命令行配置文件路径 Spec

## 背景

`cmd/server/main.go` 目前通过 `config.LoadConfig("")` 加载配置：空路径时先看 `BINRAG_CONFIG` 环境变量，再回退 `./configs/config.yaml`。无法在命令行直接指定不同的配置文件（如本地开发用的 `configs/config.local.yaml`），需要临时改环境变量或默认路径，使用不便。

## 目标

- 支持命令行 `-c <path>` / `--config <path>` 指定配置文件路径
- 优先级：命令行参数 > 环境变量 > 默认路径
- 不破坏现有用法（不带参数时行为与现状完全一致）

## 功能需求

- F1: 启动时接受 `-c` 与 `--config` 两种写法指定配置文件路径
- F2: 指定路径的优先级高于 `BINRAG_CONFIG` 环境变量与默认路径
- F3: 未指定参数时，行为与现状一致（环境变量 → 默认路径）
- F4: 指向不存在或不可读的路径时，输出清晰错误并退出，不静默回退到默认配置

## 非功能需求

- N1: 零新增第三方依赖（使用标准库 flag）
- N2: 不影响其他包与既有测试

## 不做的事

- 配置热加载 / 监听文件变化
- 多配置文件合并
- 全局命令行参数重构（-v、-h 等后续按需加）
- 修改 config.LoadConfig 的加载优先级逻辑（优先级由调用方保证）

## 验收标准

- AC1: `go run ./cmd/server -c configs/config.local.yaml` 使用指定文件（启动日志或加载行为可观测）
- AC2: `--config` 写法与 `-c` 等价
- AC3: 不带参数时仍走环境变量 → 默认路径
- AC4: `-c` 指向不存在文件时输出错误并以非零码退出
- AC5: 编译与全部测试通过
