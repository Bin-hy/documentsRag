# 引用来源查看与文档下载预览 需求

## 背景

BinRag 已完成 SSE 流式问答：回答下方展示「引用来源」卡片（文件名 + 标题 + 分数），数据来自检索结果的 payload（Qdrant 中已存 `content` / `document_id` / `kb_id` / `chunk_id`）。但存在两处能力缺口：

1. **引用不可查看**：`docs/08-前端界面/spec.md` 承诺「引用来源展示（可点击定位）」「引用来源以可点击卡片展示」（F2、AC2），但前端 `SourceCard.vue` 仅有 hover 样式、无 click 事件，后端也没有按 chunk 查内容的接口——点击引用无任何反应。数据已就绪（payload 含 chunk 原文 `content`），只缺接口与交互。
2. **文档不可查看/下载**：文档上传后原文件保存在本地磁盘 `{file_storage_dir}/{kb_id}/{doc_id}.{ext}`，元数据在 PostgreSQL（`documents` 表含 `file_path`/`filename`/`format`/`size`/`status`）。但 webui 文档列表只有元数据展示，没有查看正文或下载原文件的入口。

本需求补齐这两处：让引用来源可点击查看 chunk 原文（回答可追溯），让文档可查看详情、预览文本正文、下载原文件。

## 目标

- 问答回答中的引用来源卡片可点击，弹出该 chunk 的原文内容，实现「可点击定位」的 spec 承诺
- 文档列表提供「详情」「预览」「下载」操作：查看元数据、预览文本格式正文、下载原文件
- 全部新能力走既有认证与统一响应体系，文件路径访问安全（防路径穿越）

## 功能需求

- F1: 引用来源可点击——问答回答中的每张引用来源卡片可被点击，点击后展示该来源 chunk 的原文内容
- F2: 原文内容展示——展示内容包含 chunk 正文与来源文档名；加载失败时给出可读的错误提示，不中断页面
- F3: 文档详情——可按文档查看元数据：文件名、格式、大小、入库状态、创建时间（复用既有文档数据）
- F4: 文档预览——文本格式（如 md/txt 等）的文档返回其正文内容用于展示；二进制或不受支持的格式返回明确错误提示
- F5: 文档下载——可下载文档原文件，下载文件名正确，响应携带附件下载语义（Content-Disposition）
- F6: 前端操作入口——文档列表为每行提供「预览」「下载」操作；预览以弹窗展示正文，下载触发浏览器保存文件

## 非功能需求

- N1: 路径安全——所有按文档读取磁盘文件的操作必须基于数据库记录中的路径，并限定在配置的存储目录内（防止路径穿越）
- N2: 认证——所有新增接口与既有接口一致，要求有效的 API Key（Bearer 认证）
- N3: 错误语义——chunk 或文档不存在返回 404；格式不支持返回明确的业务错误码；服务端错误返回 500，均遵循统一响应格式
- N4: 行为一致性——有数据时的响应结构、字段命名与既有接口风格一致；空数据不返回 null（沿用 `[]` 约定）

## 不做的事

- 不做整文档的句子级定位（点击引用仅查看该 chunk 原文，不跳转文档并高亮定位）
- 不做 PDF / Office / 图片等二进制格式的在线渲染预览（仅文本格式预览，其余走下载）
- 不修改 SSE 流式问答本身（引用数据已随 SSE 下发，本次只补查看交互）
- 不做引用与知识库详情页的联动跳转

## 验收标准

- AC1: 问答回答中的引用卡片可点击，弹窗展示该 chunk 原文内容（验证：浏览器点击引用卡片，弹窗出现且内容与检索结果一致）
- AC2: 点击不存在的 chunk 引用时，弹窗提示错误且页面不崩溃（验证：构造无效 chunk id，观察错误提示）
- AC3: 文档详情可查看元数据（文件名/格式/大小/状态/创建时间）（验证：接口返回字段完整）
- AC4: 文本格式文档可预览，弹窗展示正文（验证：上传 md/txt 文档后点预览）
- AC5: 二进制/不支持格式文档预览返回明确错误（验证：上传 pdf 等后点预览，观察错误提示）
- AC6: 文档可下载，文件内容与上传一致、文件名正确（验证：下载后比对文件内容与名称）
- AC7: 路径穿越请求被拒绝（验证：构造 `../` 路径请求，返回错误而非文件内容）
- AC8: 无有效 API Key 访问新接口返回 401（验证：无/错误 Key 请求）
- AC9: `go build ./...`、`go test ./...`、`go vet ./...`、前端 `npm run build` 全部通过
