# 文件上传支持判断（Support）Spec

## 背景

系统支持文本、图片、音频、视频等多类文档入库。其中图片、音频、视频依赖外部模型能力：

- 图片 → 视觉理解（vision）
- 音频 → 语音转写（speech，即 ASR）
- 视频 → 视觉理解（vision）；抽帧策略为 scene 时额外依赖视觉 embedding（vision_embedding）

这些能力是否可用，取决于配置中是否填写了对应的 APIKey（`multimedia.vision.api_key`、`multimedia.speech.api_key`、`multimedia.video.vision_embedding.api_key`）。

现状存在两个问题：

1. 后端没有一个统一的「该文件当前是否可处理」的判断入口：格式识别与能力预检分散在两处，调用方无法一次拿到「是否支持 + 为什么」。
2. 前端文件选择器写死了一组文本扩展名（`.txt .md .pdf .docx .csv .xlsx .html`），导致即使后端配置了 vision/speech key，音频、视频、图片也无法从前端选择上传。

## 目标

- 提供一个统一的文件支持判断：系统是否认识该类型 **且** 该类型所需能力是否已配置（APIKey 就绪）。
- 后端上传预检复用它，给出可区分「格式不支持 / 能力未配置」的清晰提示。
- 前端动态获取当前支持的类型，文件选择器与拖拽校验据此过滤，用户能看到哪些类型当前不可用及其原因。

## 功能需求

- F1：对给定文件（文件名 + 可选 MIME 类型），返回判断结果：是否支持处理，以及不支持时的原因（格式不支持，或缺少哪种能力配置）。
- F2：判断规则必须依据当前生效配置：文本类无需外部能力，恒支持；图片需 vision；音频需 speech（语音转写/ASR）；视频需 vision，且抽帧策略为 scene 时额外需 vision_embedding。
- F3：后端上传预检改用该判断，对「格式不支持」与「能力未配置」分别返回可读错误。
- F4：后端提供查询入口，返回当前配置下各文件类型（扩展名 / MIME）的支持状态，含类型类别与不支持原因，供前端使用。
- F5：前端文件选择器不再写死类型，改为动态获取 F4 的支持列表，据此设置可选文件类型、拖拽校验与提示文案；不支持的类型给出原因提示。

## 非功能需求

- N1：判断逻辑与「能力配置是否就绪」同源（以服务启动时的配置为准），不缓存过期状态。
- N2：判断本身不做网络调用、不解析文件内容（纯文件元数据 + 配置判断），可安全用于上传预检与前端查询。
- N3：不泄露 APIKey 等敏感信息（对外只返回「是否配置/支持」，不返回 key 明文）。

## 不做的事

- 不改动各解析器的实际解析逻辑与转写/视觉实现。
- 不新增「内容可读性」判断（扫描件拒绝等，现有 min_readable_chars 逻辑保持不变）。
- 不探测模型服务「在线可用性」（配了 key 但服务不可达不在此范围，仅判断配置是否就绪）。

## 验收标准

- AC1：对已知文本类型（.txt/.md/.pdf/.docx/.csv/.xlsx/.html）判断结果为「支持」，且不依赖任何 APIKey。
- AC2：未配置 speech（音频 ASR）时，对 .mp3 等音频文件判断为「不支持」，原因为缺少语音转写配置；配置后变为「支持」。
- AC3：未配置 vision 时，对图片/视频判断为「不支持」，原因为缺少视觉配置；配置后图片为「支持」，视频在 fixed 策略下为「支持」，在 scene 策略且未配 vision_embedding 时为「不支持」。
- AC4：对系统完全不认识的格式（如 .exe）判断为「不支持」，原因为格式不支持。
- AC5：上传接口对「能力未配置」和「格式不支持」分别返回清晰可读的错误。
- AC6：查询入口返回的类型列表与实际判断一致；前端据此渲染文件选择器，配置了 speech 后音频类型出现在可选列表中。
- AC7：前端打开上传面板时拉取当前支持列表，配置就绪（speech 已配）的类型出现在可选列表中、未就绪的类型不可选且给出原因。
