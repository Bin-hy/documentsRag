# 多数据源与数据源注册中心 决策记录

> 对应 spec.md / plan.md / task.md / checklist.md，记录实现过程中的关键决策与取舍。

## 1. 数据源抽象独立成包（internal/datasource）

- **决策**：新建独立 `internal/datasource` 包，定义 `Source` 接口与 `Registry` 注册中心，不塞进 retriever 包。
- **理由**：数据源是「搜哪里」的抽象，retriever 是「怎么搜」的实现，职责分离；仿项目已有 `internal/loader/registry.go` 的注册表模式，后续 MCP 等可复用同一注册中心动态注册自定义源。
- **取舍**：方案 B（扩展 Retriever 为组合型）改动小但职责混杂、注册中心挂载别扭；方案 C（仅扩展 Strategy 枚举）把「搜哪」混进「怎么搜」，语义混乱。均未采用。

## 2. 数据源结果复用 retriever.RetrieveResult

- **决策**：`Source.Search` 返回 `[]retriever.RetrieveResult`，来源类型用 `Metadata["source_type"]` 标记，不进 retriever 包的类型。
- **理由**：与 `buildContext` / 上下文组装零转换衔接；引用结构 `Source.SourceType` 从 Metadata 读取（T8），前端/MCP 可区分结果来源，且不影响现有上下文模板渲染。

## 3. 私有性限定复用 StrategyConfig.DataSources 三层合并

- **决策**：`StrategyConfig` 新增 `DataSources []string`，复用现有「请求 > 知识库 > 全局」合并机制（`ResolveStrategy`），空 = 默认仅 vector_store。
- **理由**：零新机制；KB 级、请求级（MCP 纯 RAG 场景传请求参数即可）天然支持；未知源名由使用方容错，不参与 `ValidateStrategy` 校验。
- **语义**：与单值策略（高优先级非空覆盖）一致；允许集合「非空即覆盖」，不做交集（保持简单可预期）。

## 4. 私有性强制 = 模板约束 + 代码强制双保险

- **决策**：路由模板注入 allowed 说明（`routeData.AllowedText`）约束 LLM 输出范围；同时 `resolveDataSource` 在代码层强制——allowed 非空且候选不在其中 → 取 allowed 首项。
- **理由**：LLM 输出不可靠，仅靠模板提示无法保证私有性（checklist AC4）。代码强制兜底确保「限定后即使 LLM 返回 web 也不会路由过去」。

## 5. 不可用数据源自动降级

- **决策**：`resolveDataSource` 选中源未注册/`Available()==false` → 降级 `vector_store`，`slog.Warn` + 思考链路记录。
- **理由**：web_search 是占位源（未实现），路由到它时请求不能中断（checklist AC5）；降级保证「最终有答案或原有兜底文案」。

## 6. 策略组合最小化（搜哪与怎么搜不叠加）

- **决策**：`data_source ≠ vector_store` 时，跳过 multi_query / decomposition / step_back / hyde 策略增强，走常规单次数据源检索；`prepare` 内对非向量源强制 `eff.Query="single"`。
- **理由**：「数据源 × 策略」组合爆炸，本次范围只做单数据源路由；向量源行为完全不变（N1 回归兼容）。
- **代价**：web 源暂不支持多查询变体/分解等增强，后续需要时再扩展。

## 7. NewEngine 用可变参数 Option 保持兼容

- **决策**：`NewEngine(...)` 增加 `opts ...EngineOption`，`WithSources(reg)` 注入注册中心；为 nil 时内部构建默认 registry（vector_store + web 占位）。
- **理由**：现有调用方（rebuild.go / AssembleEvalDeps）零改动编译通过（N1）；app 层 `BuildRuntime` 显式构建并注入 registry，为未来动态注册自定义数据源留了挂载点。

## 8. 路由判定新增 data_source 维度（与 strategy 正交）

- **决策**：`routeResult` 增加 `DataSource` 字段；`defaultRoutingTemplate` 扩展输出 `data_source`；`routeQuery` 接收 allowed 文本。
- **理由**：strategy 表达「怎么搜」，data_source 表达「搜哪里」，正交；`RoutingData.DataSource` 随思考链路输出（N3/AC7）。
- **兼容**：自定义路由模板路径机制不变（未配置时用内置默认）；旧模板（无 data_source 字段）解析出空值 → 默认 vector_store，不破坏。

## 9. 降级目标受 allowed 集合约束（审查修复）

- **决策**：`resolveDataSource` 中候选源不可用时，降级目标**优先在 allowed 集合内选择可用源**；仅当 allowed 为空（未配置）或 allowed 内全不可用时，才降级默认向量库并输出显式 `slog.Warn`。`prepare` 层增加白名单兜底校验：若调用方指定的 `DataSource` 超出 `AllowedDataSources`，强制降级 vector_store。
- **理由**：隔离审查指出「降级/回退路径绕过 allowed 白名单」——原实现候选不可用时无条件降级 vector_store，当 allowed 不含 vector_store（如 `[web_search]`）时会用到未授权源。修复后降级不落到 allowed 之外的源。
- **语义边界**：allowed 的语义 = 「LLM 路由判定的选择范围 + 降级目标范围」。当 allowed 内无任何可用源时降级默认向量库并显式告警——vector_store 为本地内部源，不涉及外部数据外泄（核心私有性不受影响），且保证请求不中断（AC5 服务可用性）。
- **并发**：注册中心 `defaultRegistry` 增加 `sync.RWMutex`，支持运行时动态注册与多请求并发读取（防 map 竞态）。
