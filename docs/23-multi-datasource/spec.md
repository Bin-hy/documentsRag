# 多数据源与数据源注册中心 Spec

## 背景

当前 RAG 系统只有「向量知识库」一种数据来源：

- `retriever.Retriever` 是检索的唯一入口，内部固定走「embedding + Qdrant 向量检索 + BM25 + Reranker」
- RAG 路由（`routeQuery`）只决定**怎么搜**（direct / multi_query / decomposition / step_back / hyde），不决定**搜哪里**
- 查询内容不在知识库中时，只能返回固定文案「未找到相关资料。」（`engine.go` 的 `noAnswerText`）

这导致系统无法回答知识库之外的问题，数据来源单一。需要扩展出「数据源」维度：

1. 定义数据源抽象，让不同数据来源（web search、数据库、图等）接入只需实现一个接口
2. 提供数据源注册中心，支持动态注册/获取现有数据源
3. 路由判定扩展到数据源维度：LLM 判定本次查询用哪个数据源
4. 预留「仅限定的数据源」能力，保障数据私有性——后续提供 MCP 服务时，可强制只从向量库检索，提供纯粹的 RAG 结果，不路由到 web search 等外部来源

**已确认的范围（用户决策）：**

- web search 只搭框架：定义接口与注册中心，具体实现留占位（后续接入真实搜索 API）
- 触发方式：仅 LLM 路由判定（routing=auto 时由 LLM 选数据源），不做空结果自动兜底

## 目标

- 数据源接入成本低：新增数据源只需实现一个接口并在注册中心注册
- 路由判定可输出数据源选择，并能正确路由
- 私有性可控：可限定本次请求/知识库/全局允许的数据源，限定后不会路由到限定外的数据源
- 现有向量检索路径在未配置新功能时行为完全不变

## 功能需求

- F1: 数据源抽象接口。定义数据源统一接口，包含：数据源名称、可用性（是否已实现/可用）、检索方法（接收查询与限制参数，返回统一结构的检索结果）。不同数据源只需实现该接口即可接入。
- F2: 数据源注册中心。提供注册、按名称获取、列出全部数据源的能力；支持运行时动态注册（动态加载）。
- F3: 内置向量库数据源。注册一个包装现有检索能力的向量库数据源，作为默认数据源；其行为与现有检索路径一致（含向量 + BM25 + 重排）。
- F4: web search 占位数据源。注册名为 web_search 的数据源，但标记为「未实现/不可用」；调用其检索方法时返回明确错误（或空结果 + 不可用标记），不产生真实网络请求。
- F5: 路由判定数据源维度。routing=auto 时，路由判定输出除了现有复杂度/策略外，新增数据源选择（如 vector_store / web_search）；判定结果决定本次查询走哪个数据源。
- F6: 私有性限定。提供「允许的数据源」配置，分三层：全局默认 → 知识库（KB）级配置 → 单次请求参数，优先级请求 > KB > 全局。限定的含义：路由判定只能在允许的数据源集合内选择；若允许集合为空或未配置，默认仅向量库数据源。MCP 等场景可通过请求参数强制「仅向量库」。
- F7: 路由到不可用数据源时的降级。路由判定选择了未实现/不可用的数据源时，自动降级回退到默认可用数据源（向量库），不中断请求、不报错。
- F8: 结果与引用集成。数据源检索结果进入现有上下文组装与引用体系；引用/思考链路可区分结果来源类型（如向量库 / web）。
- F9: 路由判定模板扩展。默认路由模板扩展为输出数据源维度；自定义模板路径机制保持兼容（未配置时用内置默认）。

## 非功能需求

- N1: 兼容性——未配置任何新字段（数据源限定、新路由模板）时，现有检索行为与结果完全一致（回归兼容）。
- N2: 扩展成本——接入一个新数据源 = 实现接口 + 注册中心注册一行，不改动 RAGEngine 核心逻辑。
- N3: 思考链路——数据源选择作为思考链路的一步可观测（thinking 输出可见），便于调试。
- N4: 配置向后兼容——已有配置项含义不变，新增字段均为可选。

## 不做的事

- 不实现真实 web search 后端（仅占位注册，接口就绪）
- 不做空结果自动兜底 web search（用户已确认仅 LLM 路由判定触发）
- 不做 MCP 服务本体（仅预留请求级数据源限定能力，供 MCP 场景调用）
- 不做多数据源并行检索与跨源融合（本次为单数据源路由：每次查询路由到一个数据源）
- 不新增数据源类型（如数据库/图）的具体实现，仅预留抽象能力

## 验收标准

- AC1: 数据源接口可被实现；注册中心支持注册、按名称获取、列出全部数据源。
- AC2: 系统启动后默认注册了向量库数据源（可用）与 web_search 占位数据源（不可用）。
- AC3: routing=auto 时，路由判定结果包含数据源维度；在 mock LLM 返回 vector_store 时实际走向量库检索，返回 web_search 时走 web 数据源。
- AC4: 限定数据源集合为仅 vector_store 时，即使路由判定（mock）返回 web_search，实际也不会路由到 web，而是用向量库。
- AC5: 路由判定返回 web_search 且 web 不可用时，请求正常降级为向量库检索，不报错、最终有答案或原有兜底文案。
- AC6: 不配置任何新字段时，现有单测全绿、现有检索行为不变。
- AC7: 数据源选择出现在思考链路中（thinking 输出含数据源信息）。
- AC8: 新增数据源的接入流程有文档说明（接口 + 注册 + 限定配置示例）。
