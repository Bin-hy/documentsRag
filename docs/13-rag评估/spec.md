# RAG 评估与优化 Spec

## 背景

BinRag 已完成完整 RAG 链路（入库、混合检索、重排序、LLM 生成、API/前端），但**没有任何量化评估手段**——无法知道检索是否命中正确内容、回答是否准确、是否忠实于检索资料。`docs/00-开发路线图.md` 阶段八「评估与优化（持续）」列明：构建评估数据集、Recall@K、LLM-as-Judge、忠实度等指标，但尚未实施。

本阶段构建可复用的评估框架：数据集格式 + Recall@K 检索指标 + LLM 评估指标（准确性与忠实度），以独立 CLI 提供评测入口，为后续分块/Embedding/Prompt 调优提供量化依据。

## 目标

- 提供评估数据集格式（问题 + 标准答案 + 期望检索片段），支持加载与校验
- 提供 Recall@K 检索命中率指标：对每个问题跑检索，统计期望片段出现在前 K 结果中的比例
- 提供 LLM 评估指标：答案准确性（LLM-as-Judge）与答案忠实度（是否基于检索内容）
- 提供独立 CLI 评测入口：加载配置与数据集，逐条评估，输出结构化报告
- 指标可分别运行（仅检索 / 仅问答 / 全量），支持逐步调优

## 功能需求

- F1: 数据集定义——评估数据集由多条样本组成，每条含问题、标准答案、期望检索片段标识、可选的知识库范围；数据集以文件形式提供，加载时校验结构完整
- F2: 检索评估——对每条样本执行检索（复用现有检索链路，含向量+BM25+RRF+重排序），按期望片段是否出现在前 K 结果中计算 Recall@K（K 可配置，默认评估 K=1/3/5）
- F3: 问答评估——对每条样本执行问答（复用现有 RAG 编排），收集回答与引用来源
- F4: 准确性指标——用评审模型（LLM-as-Judge）对「回答 vs 标准答案」评分，输出每样本分数与总体平均
- F5: 忠实度指标——用评审模型判断回答是否基于检索到的引用来源（不编造），输出每样本判定与总体比例
- F6: 报告输出——评测结束输出汇总：样本数、Recall@K、平均准确性、忠实度比例，以及逐样本明细（问题/回答/分数/判定）
- F7: 分项运行——支持仅检索评估、仅问答评估、全量评估三种模式，避免重复跑检索
- F8: 可复现——固定随机种子与模型参数，同一数据集重复运行结果一致（除 LLM 生成本身的不确定性外）

## 非功能需求

- N1: 复用现有组件——检索走现有 retriever，问答走现有 rag.Engine，评审走现有 llm，不重复实现
- N2: 配置驱动——评测配置（数据集路径、K 值、评审模型、是否跑 LLM 指标）从配置文件/命令行参数读取
- N3: 容错——单条样本检索/问答/评分失败不中断整体，记录错误并继续
- N4: 性能——评测可并行（检索/问答样本级并发），有并发上限配置，避免打爆 API
- N5: 评审一致性——LLM-as-Judge 使用确定性优先设置（低温度），评分标准以提示词形式固化

## 不做的事

- 不自动调优（本阶段只提供评估手段，不做 A/B 对比编排与自动选优，留待后续）
- 不生成评测数据集内容（数据集由人工或外部构建，本阶段只定义格式与加载）
- 不改动现有检索/问答/RAG 编排的任何行为（纯新增评估层）
- 不做前端评测页面（CLI 足够，后续按需）
- 不做检索结果可视化（报告为文本/JSON）

## 验收标准

- AC1: 提供数据集格式定义与示例，加载器可读取合法数据集、拒绝格式错误数据集（验证：示例数据集加载成功，错误数据集报错）
- AC2: 检索评估可运行——对含期望片段的数据集输出 Recall@1/3/5（验证：CLI 运行检索模式，输出含三个 K 值）
- AC3: 问答评估可运行——输出每样本回答与引用来源（验证：CLI 运行问答模式，报告含回答明细）
- AC4: 准确性指标可运行——输出每样本 LLM 评分与平均分（验证：配置评审模型后运行，报告含分数）
- AC5: 忠实度指标可运行——输出每样本判定与忠实比例（验证：报告含 faithful/unfaithful 判定）
- AC6: 分项运行生效——仅检索模式不调用 LLM 生成与评审（验证：日志/耗时观察无 LLM 调用）
- AC7: 容错生效——数据集含一条故意失败样本（如期望片段不存在），评测不中断且报告标记该样本错误（验证：运行观察）
- AC8: `go build ./...`、`go test ./...`、`go vet ./...` 全部通过
