# RAG 路由 + HyDE 决策记录

> 本文档记录阶段三（RAG 路由 + HyDE）实现过程中的关键技术决策、理由与权衡，供阶段四（策略可选化配置）与后续参考。

## 决策 1：HyDE 采用「引擎内嵌 embedder」真向量检索

**选择：** RAGEngine 持有 `embedding.Embedder`（`NewEngine` 新增参数），HyDE 生成假设文档 → `embedder.Embed` → `retriever.SearchByVector`（新增的按向量检索方法）→ 与原查询 `Search` 结果 `FuseMultiQuery` 融合。

**理由：** 用户确认「引擎内嵌 embedder（推荐）」；这才是真正的「用假设文档向量检索」（HyDE 的核心语义），而非把假设文档文本当查询走普通 embed（后者无法利用「答案-答案相似度高于问题-答案」的特性）。

**影响：** `NewEngine` 签名变更（+emb 参数），app.go 两处装配与 engine_test 18 处调用同步修改；`Retriever` 接口新增 `SearchByVector`，所有 fake 实现需补。

## 决策 2：HyDE 融合用 FuseMultiQuery（HyDE 路 + 原查询路）

**选择：** HyDE 向量检索结果与原查询检索结果作为两路，`retriever.FuseMultiQuery`（RRF）融合取 Top-K。

**理由：** 复用阶段一的融合函数；HyDE 路提供语义互补（假设文档更贴近答案表达），原查询路保底（假设文档可能偏离）；双路 RRF 提升召回稳健性。

## 决策 3：路由判定失败回退到默认策略（而非落常规）

**选择：** `routeQuery` 解析失败/异常时，`strategy = RoutingFallback`（默认 `multi_query`），日志记录降级。

**理由：** spec 要求「判定失败回退默认策略不阻塞」；回退到 multi_query（中等成本）比落常规（可能漏召回）更符合增强意图；避免简单问题因路由失败而绕开检索增强。

**注意：** 测试中发现 `testRoutingCfg` 直接构造 RAGConfig 不经过 `applyDefaults`，需显式设 `RoutingFallback`（生产配置由 LoadConfig 的 applyDefaults 保证默认值）。

## 决策 4：HyDE 接入 prepare 常规检索环节（非多查询路径）

**选择：** HyDE 在 `prepare` 的单查询检索处接入：`HyDEOn && embedder != nil && !MultiQueryOn` 时用 `hydeSearch` 替代 `retriever.Search`。

**理由：** 常规路径是 HyDE 收益最大处（查询-文档不对称最明显）；与 Multi-Query 互斥（两者都做双路检索成本过高）；路由的 direct 策略落常规即享受 HyDE，decomposition 的子问题检索通过 `searchSubQuery` 亦可叠加（子问题走 Search 单路，若 HyDEOn 需手动接入——当前版本 searchSubQuery 未接 HyDE，见 TODO）。

**TODO（后续）：** `searchSubQuery`（阶段二）未接入 HyDE；若需 decomposition 子问题也享受 HyDE，在阶段四策略配置时统一接入。

## 决策 5：HyDESkipSimple 默认 true（nil 视为 true）

**选择：** `HyDESkipSimpleOn()` 对 nil 返回 true——简单查询跳过 HyDE。

**理由：** 简单查询 HyDE 收益低（问题已明确）、成本高（+1 LLM +1 Embedding）；默认跳过节省配额。注意：skip 判定依赖路由的 complexity 字段，**无路由时 complexity 未知按非 simple 处理（HyDE 生效）**——测试 TestAsk_HyDESkipSimple 已标注此语义。

## 决策 6：路由判定用低温度（0.0）+ JSON 输出

**选择：** `routeQuery` 用 `WithTemperature(0.0)` 并解析 `{complexity, strategy, reasoning}` JSON。

**理由：** 路由是分类决策，确定性优先；reasoning 字段供日志与后续调试；与阶段二判定模板风格一致。

## 配置项汇总

| 配置 | 默认 | 说明 |
|------|------|------|
| `routing_enabled` | false | 是否启用 RAG 路由 |
| `routing_fallback` | multi_query | 路由判定失败回退策略 |
| `hyde_enabled` | false | 是否启用 HyDE 假设文档 |
| `hyde_skip_simple` | true | 简单查询是否跳过 HyDE |
| `routing_template_path` | 空 | 路由判定模板路径 |
| `hyde_template_path` | 空 | 假设文档生成模板路径 |

## 与阶段四（策略可选化）的关系

- 本阶段的路由判定（routeQuery）将成为阶段四策略配置的**自动模式**（用户可关闭路由改手动指定 strategy）
- HyDE 的 `hyde_enabled` / `hyde_skip_simple` 将成为策略配置项，支持知识库级/请求级覆盖
- `NewEngine` 的 embedder 参数已就绪，阶段四策略配置无需再改装配
