# Decomposition 问题分解 + Step-Back 回退 Spec

## 背景

BinRag 已实现阶段一的 Multi-Query 多查询 + RAG-Fusion（多路检索提升召回）。但对**复杂复合问题**（含多个信息需求、需对比分析、多步骤解答）仍不够——单次检索（即使多路）无法覆盖问题的全部维度；对**需要高层概念/多步推理**的问题（时间序列、趋势、抽象理解），直接检索原始问题可能召回泛化不足。

`docs/15-rag优化计划.md` 阶段二（P1）：引入 **Decomposition 问题分解**（复杂问题拆子问题逐个击破）与 **Step-Back 回退查询**（先生成抽象回退问题检索广泛上下文）。两者**互斥**（默认），由独立开关 + LLM 判定启用。

## 目标

- 复杂复合问题被识别并分解为子问题，逐个子问题检索、综合回答，覆盖完整信息需求
- 需要高层抽象的问题先生成回退问题检索，再结合原问题精答
- 两者作为可选策略：独立开关控制，LLM 判定是否适用（简单问题跳过），与阶段一 Multi-Query 协同

## 功能需求

- F1: 复杂度判定——启用 Decomposition 时，LLM 先判断问题是否适合分解（简单事实查询/定义类 → 跳过走常规路径；复合/对比/多步骤 → 分解）
- F2: 问题分解——判定为复杂时，LLM 输出子问题列表（数量受上限约束），支持**并行**与**顺序**两种模式（顺序模式下子问题答案可作为后续子问题的输入参考）
- F3: 子问题检索——每个子问题走检索路径（复用现有混合检索，Multi-Query 可选叠加），收集各子问题检索结果与答案
- F4: 综合回答——LLM 结合所有子问题答案与原始问题生成最终回答，引用来源覆盖各子问题的检索结果
- F5: Step-Back 判定与回退——启用 Step-Back 时，LLM 判断是否需要抽象回退（时间/趋势/高层概念类 → 是），生成抽象回退问题，用回退问题检索广泛上下文
- F6: 最终生成——Step-Back 路径：回退上下文 + 原问题检索结果共同注入生成，回答结合两者
- F7: 互斥——同一查询只走 Decomposition 或 Step-Back 之一（Decomposition 优先；两者都启用时仅 Decomposition），避免叠加复杂化
- F8: 降级——任一策略的 LLM 调用/解析失败时降级为常规路径（单查询/多查询 + 直接生成），问答不中断

## 非功能需求

- N1: 配置驱动——`decomposition_enabled`、`decomposition_mode`（parallel/sequential）、`decomposition_max_sub`（默认 5）、`step_back_enabled` 均可配置，默认关闭（保持现状）
- N2: 成本权衡——分解/回退新增 LLM 调用（判定 + 生成子问题/回退问题 + 综合），仅在判定为适用时启用；文档标注延迟/成本增加
- N3: 与阶段一协同——Decomposition 子问题检索可叠加 Multi-Query（若启用），Step-Back 的回退检索不叠加（保持简单）
- N4: 可观测——日志记录判定结果（是否分解/回退、子问题列表、回退问题）、各阶段耗时与调用数，供评估对比
- N5: 兼容——未启用时行为与现状完全一致；引用来源、SSE 事件流、历史记录结构不变

## 不做的事

- 不做路由（阶段三）——本阶段不自动分流 simple/medium/complex，靠开关 + 判定
- 不做 Decomposition 与 Step-Back 叠加（已决策互斥）
- 不做子问题间的依赖图/层次分解（仅并行与顺序两种模式）
- 不做分步生成子答案的持久化缓存（每次问答独立）
- 不改 Multi-Query / 混合检索 / 重排序的实现

## 验收标准

- AC1: 启用 Decomposition 且问题被判定为复杂时，日志显示子问题列表并逐个检索（验证：日志含「分解为 N 个子问题」与多路检索记录）
- AC2: 并行模式子问题独立检索、顺序模式子问题答案作为后续输入（验证：单测断言两种模式的检索顺序/输入差异）
- AC3: 综合回答基于所有子问题答案，引用来源覆盖各子问题（验证：集成测试 Sources 非空且来自各子问题检索）
- AC4: 简单问题被判定为不适合分解时走常规路径（验证：单测——判定返回跳过，检索数与常规一致）
- AC5: 启用 Step-Back 且判定需要回退时，日志显示回退问题并检索（验证：日志含「回退问题」与检索记录）
- AC6: Step-Back 回答结合回退上下文与原问题检索（验证：单测断言消息含两类上下文）
- AC7: 两策略互斥——同时启用时仅 Decomposition 生效（验证：单测断言 Step-Back 判定未被调用）
- AC8: 任一策略失败降级常规路径，问答不中断（验证：mock LLM 失败，观察降级且回答正常）
- AC9: 未启用时行为与现状完全一致（验证：现有测试不回归；关闭配置跑 eval 基线）
- AC10: `go build ./...`、`go test ./...`、`go vet ./...` 全部通过
