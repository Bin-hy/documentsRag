# 增强模式与 websearch（function calling）决策记录

> 对应已批准的分层计划与 docs/24-websearch-enhanced/spec.md，记录关键决策与取舍。

## 1. 真 function calling（用户决策）

- **决策**：扩展 LLM 层支持 OpenAI tools 参数与 tool_calls 响应（`Message.ToolCalls/ToolCallID/RoleTool`、`FunctionTool`、`GenerateTool`），而非语义化 Tool 封装。
- **理由**：用户明确选择「真 function calling」；qwen2.5 系列支持 tools。改动面：llm 请求/响应/流式 + RAG tool loop。

## 2. 可插拔 Search Provider + 博查第一版（用户决策）

- **决策**：`internal/search` 包定义 `Provider` 接口（Name/Available/Search），`New(cfg)` 工厂按 `provider` 字段选择；博查 Bocha 为第一版实现（POST /v1/web-search，Bearer key，返回 title/url/summary/content/site）。
- **理由**：国内可用、中文友好；接口解耦便于后续换 Tavily/自建。未配置 api_key 时 `Available()==false`（增强面板标不可用、不注册工具）。

## 3. 增强模式 tool loop（RAG 层）

- **决策**：`AskOptions.Enhanced` + `WithEnhanced`；`runToolLoop` 用 `GenerateTool` 多轮调用（上限 `maxToolRounds=3`），工具结果以 `role=tool` 消息回传；未知工具回传错误文本。
- **无工具回退**：注册中心为空（未配置搜索 key）时，增强模式回退普通生成（N1 回归兼容，单测覆盖）。
- **web_search 工具**：JSON Schema 参数（query 必填/count 可选），结果格式化为「标题+链接+摘要+正文截断(800 字符)」回传 LLM。

## 4. 流式增强：先静默 tool loop 再输出（N2）

- **决策**：StreamAsk 增强模式下，先非流式 `GenerateTool` 完成 tool loop，最终回答一次性 `EventChunk` 发出。
- **理由**：SSE 事件序列保持 thinking → sources → chunk → done 简单不变；避免前端处理复杂 tool 流。代价：增强流式回答非增量（可接受，联网搜索本身耗时）。
- llm 层仍实现了流式 delta.tool_calls 聚合（`StreamChunk.ToolCalls`），为未来纯流式 tool loop 预留。

## 5. 前端增强面板（多能力预留）

- **决策**：`ChatView` 提问区「增强：联网搜索」开关（el-checkbox）→ chat store `enhanced` → 请求体 `enhanced`；`GET /api/v1/chat/enhancements` 返回能力列表（web_search + available），未来新增能力扩展数组即可。
- **StepTool 渲染**：ThinkingPanel 新增 `type==='tool'` 分支（工具/参数/结果/错误），typeLabels 增加「工具调用」。

## 6. 集成装配

- **决策**：`app.BuildRuntime` 中 `search.New(cfg.WebSearch)` → `rag.WithSearchProvider`；Provider 可用时 `NewEngine` 自动注册 web_search 工具。配置段 `web_search: {provider, base_url, api_key, count, timeout, qps}`（默认 bocha/count=5/timeout=30/qps=1）。
