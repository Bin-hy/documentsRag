# 文档分块器 Spec

## 背景

BinRag 文档加载器已完成，能将多种格式文档转换为结构化的 `*Document`（含有序 Block 列表）。分块器是 Pipeline 的第二个环节，负责将加载器输出的文档切分为适合 Embedding 模型处理的文本块（Chunk），供后续向量化和检索使用。

## 目标

- 接收加载器输出的 `*Document`，输出有序的 Chunk 列表
- 支持 3 种分块策略：固定大小、递归字符、Markdown 标题
- 以 Token 数作为分块大小的度量单位
- Chunk 携带来源追溯信息（源文档关联、位置索引、所属标题上下文）
- Tokenizer 可替换（默认内置估算器，支持注入精确实现）

## 功能需求

- F1：统一输入接口 — 接收加载器输出的 `*Document`，内部处理 Block → 文本的拼接逻辑（标题加层级前缀，列表项加标记等）
- F2：固定大小分块 — 按配置的 token 数切分文本，支持固定 token 数的重叠（overlap）
- F3：递归字符分块 — 按优先级依次尝试分隔符（段落 → 句子 → 词）拆分，确保每个 chunk 不超过 token 上限
- F4：Markdown 标题分块 — 利用 Block 的标题层级信息，按指定层级切分（如按 h2 切分），每个 chunk 为一个标题节下的完整内容
- F5：来源追溯 — 每个 Chunk 携带：源文档文件名、在文档中的序号索引、所属标题上下文路径（如 "主标题 > 二级标题"）
- F6：Tokenizer 可替换 — 定义 Tokenizer 接口，内置简单估算器作为默认实现，支持注入 tiktoken 等精确实现
- F7：策略可配置 — 通过配置选择分块策略，配置项包括：策略类型、chunk_size（token 数）、overlap（token 数）、Markdown 分块的目标层级
- F8：策略可扩展 — 支持注册自定义分块策略，无需修改现有代码

## 非功能需求

- N1：内存效率 — 分块过程中不复制整个文档内容，按 Block 逐步处理
- N2：并发安全 — 分块器实例无共享可变状态，多个 goroutine 可并发调用
- N3：可测试性 — 每种策略可独立单元测试，Tokenizer 可 mock
- N4：性能基线 — 1000 个 Block 的文档分块耗时不超过 50ms（使用默认估算器，非硬性指标）
- N5：零外部依赖 — 默认实现不引入 tiktoken 等外部依赖，精确 tokenizer 由调用方注入

## 不做的事

- 不做 Embedding 生成（属于下一阶段职责）
- 不做向量存储
- 不做语义分块（基于 Embedding 相似度的分块，属于进阶功能）
- 不做文档加载（输入已是加载器的输出）
- 不做 Chunk 去重或合并
- 不做多语言分句规则适配（使用通用标点分句）

## 验收标准

- AC1：传入含多段落的 Document，固定大小策略输出的每个 Chunk token 数不超过配置的 chunk_size
- AC2：配置 overlap=50，相邻 Chunk 之间存在约 50 token 的重叠内容
- AC3：递归字符分块在段落边界处优先切分，不在词中间断开
- AC4：Markdown 标题分块按 h2 切分时，每个 Chunk 包含一个 h2 节下的完整内容，且 Chunk 元数据包含标题上下文路径
- AC5：每个 Chunk 携带源文档文件名、序号索引、所属标题上下文
- AC6：注入自定义 Tokenizer 后，分块结果按自定义 token 计数切分
- AC7：注册自定义分块策略后，可通过配置选择使用
- AC8：单元测试覆盖 3 种策略，使用 mock Tokenizer 验证切分逻辑正确
