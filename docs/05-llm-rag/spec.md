# LLM 集成与 RAG 编排 Spec

## 背景

BinRag 已完成文档入库链路（Load → Chunk → Embed → Store）和检索链路（向量检索 + BM25 混合召回 + RRF 融合 + Cross-encoder 重排序），能够从知识库中召回高质量的文本片段。但系统尚无大语言模型接入，无法回答用户问题。

本阶段补齐生成层：接收用户问题，结合检索结果与多轮对话上下文，调用 LLM 生成带来源引用的回答，打通「提问 → 改写 → 检索 → 组装 → 生成」的完整 RAG 链路。

## 目标

- 提供统一的 LLM 客户端，支持普通生成与流式生成（OpenAI 兼容接口，与 Embedder/Reranker 的配置与重试风格一致）
- 提供 RAG 编排器，串联 Query 改写 → 检索 → 上下文组装 → Prompt 构建 → LLM 生成 → 回答输出
- 支持多轮对话：对话历史的管理与注入
- Prompt 模板管理：系统提示词、上下文注入、引用来源标注
- 全部参数配置化驱动，单元测试覆盖核心链路

## 功能需求

- F1: 普通生成——接收消息列表（系统 / 用户 / 助手角色），返回完整生成文本
- F2: 流式生成——以增量片段的方式返回生成内容，调用方可以逐段消费
- F3: 提供者接入——通过 OpenAI 兼容接口（chat/completions）调用后端，支持 base_url、api_key、model、temperature、max_tokens 等配置；未配置 API Key 时允许无鉴权调用（本地模型场景）
- F4: 错误处理——网络错误、5xx、429 自动重试（指数退避），非重试错误（如 400）直接返回失败
- F5: Query 改写——检索前将用户问题连同对话历史交给 LLM 改写，使问题自包含、可独立检索；改写结果仅用于检索，回答生成仍使用原始问题
- F6: RAG 编排入口——接收用户问题与可选对话历史，执行 改写 → 检索 → 上下文组装 → 生成，返回回答及引用来源
- F7: 流式 RAG——以流式方式生成回答，引用来源与普通 RAG 一致
- F8: 上下文组装——将检索到的文本片段按序组装为上下文，按 token 预算截断，且注入片段数不超过配置上限
- F9: Prompt 模板管理——系统提示词、上下文注入、引用标注均可通过配置替换模板；未配置时使用内置默认模板
- F10: 引用来源标注——回答附带检索来源信息（如文件名、标题上下文），供调用方展示
- F11: 对话历史管理——提供历史存取接口与内存实现；设置容量上限，超出时丢弃最旧消息；按配置决定注入生成的消息条数
- F12: 配置化驱动——llm 与 rag 的全部参数通过 config.yaml 统一管理

## 非功能需求

- N1: 生成延迟——单轮 RAG 回答的延迟以 LLM API 为主，改写 + 检索 + 组装阶段控制在 P99 < 2s（千级文档规模）
- N2: 并发安全——LLM 客户端与 RAG 编排器支持并发调用，对话历史内存实现线程安全
- N3: 可降级——检索结果为空时生成「未找到相关资料」类回答，不 panic；LLM API 不可用时返回明确错误
- N4: 可观测——改写、检索、组装、生成各阶段耗时与关键数据（上下文 token 数、引用数量）通过日志输出
- N5: 上下文预算——组装时按 token 预算截断，防止超出模型上下文窗口

## 不做的事

- HTTP API / SSE 传输层（阶段七实现）
- 对话历史的数据库持久化（阶段七引入元数据存储时一并做）
- 语义缓存、检索结果缓存
- 多模态输入（图片、表格）
- Agent 工具调用
- 多租户隔离

## 验收标准

- AC1: 调用普通生成接口，返回完整生成文本（mock LLM 服务器验证）
- AC2: 调用流式生成接口，增量片段按序返回，拼合后与普通生成内容一致
- AC3: 配置化生效——修改 config 中的 model / base_url / temperature 后，请求按新配置发出（mock 断言请求体）
- AC4: 重试逻辑——mock 服务器连续返回 500/429 后成功，调用成功；返回 400 时不重试、直接失败
- AC5: Query 改写——提供对话历史时，改写请求携带历史上下文，改写后的查询用于检索（mock 断言）
- AC6: RAG 编排——提问后返回回答及引用来源列表，引用来源与检索结果对应
- AC7: 流式 RAG——流式回答携带的引用来源与普通 RAG 一致
- AC8: 上下文组装——检索片段超出预算时被截断，注入片段数不超过配置上限（mock 断言请求内容）
- AC9: 对话历史——多轮提问后历史可读取；超过容量上限时最旧消息被丢弃；注入条数受配置控制
- AC10: 降级——检索结果为空时返回「未找到相关资料」类回答，不 panic
- AC11: 模板可替换——替换系统提示词模板配置后，生成请求中的系统提示词随之变化（mock 断言）
- AC12: 可观测——日志中能观察到改写 / 检索 / 组装 / 生成各阶段耗时
- AC13: 并发安全——多 goroutine 并发调用不 panic、无数据竞争（go test -race 通过）
- AC14: 编译通过 `go build ./...`，所有单元测试通过 `go test ./...`
