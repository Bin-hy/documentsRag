# RAGAS 评测系统 Spec

## 背景

BinRag 已完成完整 RAG 链路（入库、混合检索、重排序、LLM 生成、API/前端），并已有自研评估模块 `internal/eval`（Recall@K + LLM-as-Judge，见 `docs/13-rag评估`）。但自研评估存在局限：

- 生成侧指标口径简单（准确性/忠实度二值判断），缺少业界标准的多维度指标体系
- 无上下文精确率/召回率等检索侧细粒度指标
- 无评测任务管理、历史报告留存与多次评测对比能力

本阶段引入业界标准框架 **RAGAS**，构建独立的 Python 评测微服务（uv 包管理），通过 HTTP 与 Go 后端交互，与 `internal/eval` 并存互补：`internal/eval` 保留 Recall@K 检索指标（需进程内访问 retriever），RAGAS 服务负责生成侧与上下文侧四指标（天然黑盒、可走 HTTP）。同时在前端新增「评测中心」页面，提供发起评测、进度跟踪、报告查看与结果对比能力。

## 目标

- 提供独立 Python 微服务（uv + FastAPI）封装 RAGAS，通过 HTTP 调用 BinRag Go 后端采集检索上下文与回答，运行 RAGAS 标准四指标评测
- Go 与 Python 之间全部走 HTTP 交互：Go 侧新增统一代理路由与评测所需的数据出口，Python 服务不直接访问 Go 进程内部
- 评测为异步长任务：提交任务 → 轮询进度 → 获取结构化报告，支持取消
- 前端新增评测中心：发起评测、任务列表、报告可视化（指标汇总 + 逐样本明细 + 单样本下钻）、多次评测对比
- 复用项目已有的 LLM / Embedding 提供商配置（OpenAI 兼容接口），评审提示词中文化以保证中文语料评测质量
- 报告持久化留存，含配置快照，支撑多次评测横向对比与可复现

## 功能需求

- F1: 数据集复用与校验——评测数据集复用 `internal/eval` 的 EvalSample 格式（question / answer / expected_ids / kb_id），支持上传与预览；无标准答案（reference）的样本自动降级可用指标并明确标注
- F2: 数据采集——Python 服务通过 HTTP 调用 Go 问答接口逐样本获取回答与检索上下文正文；Go 问答接口支持附带检索上下文正文的出口参数，保证「评测所见即生成所用」
- F3: RAGAS 四指标评测——faithfulness（忠实度）、answer_relevancy（答案相关性）、context_precision（上下文精确率）、context_recall（上下文召回率，依赖标准答案）；各指标使用中文评审提示词，评审模型与生成模型可独立配置
- F4: 异步任务模型——评测任务状态机（待处理 → 采集中 → 评测中 → 完成/失败/已取消）；样本级失败不中断整体并记录错误；支持取消；服务重启后任务可恢复
- F5: 并发与限流——任务数、样本采集并发、评审模型调用速率三层限额可配置，避免打爆 LLM API
- F6: 报告输出与持久化——评测结束产出四指标汇总分数与逐样本明细（问题/回答/上下文/各指标分数/判定理由），报告持久化并携带配置快照（数据集哈希、评审模型、RAGAS 版本、提示词版本）
- F7: HTTP 接口契约——Python 服务暴露评测任务提交、状态查询、报告获取、数据集管理、健康检查等 REST 接口；前端经 Go 后端统一代理访问（复用现有鉴权与响应包装），Go 代理注入内部令牌并校验知识库越权
- F8: 前端评测中心——评测任务列表、发起评测表单（知识库/数据集/指标/评审模型选择，数据集预览与校验）、任务进度轮询（隐藏暂停、退避、终态清理）、报告页（指标汇总可视化 + 明细表格 + 低分过滤 + 单样本下钻）、多次评测对比视图
- F9: 容错与降级——评审模型解析失败有限重试后记录失败率并单独上报，失败率超阈值时评测结论标记不可靠；单样本采集失败不阻断任务

## 非功能需求

- N1: 配置驱动——评测服务的数据源地址、内部令牌、评审模型、Embedding 模型、并发限额均从配置/环境变量读取
- N2: 可复现——评审模型低温度确定性优先；同一数据集与配置重复运行结果一致（除 LLM 生成本身不确定性）；报告含配置快照
- N3: 安全——Python 服务仅内网可达（不发布宿主端口）；Go 代理统一鉴权；知识库级权限隔离在代理层校验
- N4: 部署一体化——docker-compose 新增评测服务，一键随主栈启动；依赖锁定（uv.lock）保证镜像可复现
- N5: 与现有体系并存——不改动 `internal/eval` 既有行为；两套体系口径差异在文档中明示，报告不直接互比
- N6: 中文语料质量——评审提示词中文化并配 few-shot 示例与回归样本，提示词版本化管理

## 不做的事

- 不做评测数据的在线实时评估（Go 主动推送模式留待后续）
- 不做自动调优编排（A/B 对比选优留待后续；本期仅提供多次评测结果的对比展示）
- 不替换或删除 `internal/eval`（Recall@K 仍由其负责）
- 不做评测数据集内容的人工生产工具（合成数据集生成提示词仅提供草案，不纳入本期功能）
- 不做多副本水平扩容（评测服务单副本，垂直扩容）
- 不改动现有检索/问答/RAG 编排的默认行为（仅新增可选出口参数）

## 验收标准

- AC1: uv 管理的 Python 评测服务可启动，健康检查接口返回正常；`uv.lock` 锁定依赖（验证：docker-compose 或本地 uv 启动，请求健康检查）
- AC2: 上传合法 EvalSample 格式数据集可预览与校验，格式错误被拒绝并提示（验证：前端/API 各传一份正确与错误数据集）
- AC3: 提交评测任务后可通过接口查询状态流转（待处理→采集中→评测中→完成），进度可见（验证：用 ≥5 条样本的数据集发起评测并轮询）
- AC4: 评测完成输出四指标汇总分数与逐样本明细，明细含各指标分数与判定理由（验证：查看报告）
- AC5: 无标准答案的数据集自动降级：context_recall 跳过并标注，其余指标正常（验证：用无 answer 字段的数据集评测）
- AC6: 单样本采集失败不中断任务，报告中标记该样本错误（验证：数据集含一条指向不存在知识库的样本）
- AC7: 取消运行中的任务生效，状态变为已取消（验证：评测中途调用取消接口）
- AC8: 前端评测中心可用：发起评测、进度跟踪、报告可视化、单样本下钻、两次评测对比（验证：页面走完整流程）
- AC9: 前端未经 Go 代理无法直接访问 Python 服务（验证：直接请求 Python 服务端口被拒/无令牌 401）
- AC10: 评审提示词中文输出判定理由，解析失败率有统计上报（验证：查看报告中 reason 字段与失败率指标）
- AC11: `go build ./...`、`go test ./...`、`go vet ./...` 通过；Python 服务 lint/测试通过
